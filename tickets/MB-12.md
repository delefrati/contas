Writing the manual (MB-10) turned up four bugs a member runs into. Three are in the Financeiro and
one is on the sign-in page, and two of them make the app speak English in the middle of
Portuguese. The manual works around them today; this fixes them and takes the workarounds out.

- **Deleting an entry asks the wrong question:** `Finance.vue` confirms the delete with
  `expenses.successDelete` ("Despesa removida com sucesso!"), before anything was removed, and
  shows the same text as the error when the delete fails. Ask with a new
  `expenses.confirmDelete` that names the entry ("Remover o lançamento "{name}"?"), and fail
  with a new `expenses.deleteError`, in `pt.json`, `en.json` and `es.json`.
- **The entry's Observação is never saved:** the add form has the field, but the `expenses`
  table has no column for it and the API drops it. Add a nullable `notes` text column with a
  Prisma migration, accept and return it in `POST` and `PATCH /api/expenses`, and show it in the
  edit form and under the entry in the list. Entries saved before keep no notes.
- **" (disabled)" in English:** the member lists in the add and filter forms mark inactive members
  with a hard-coded `' (disabled)'`. Use the existing `report.inactive` ("Inativo") instead.
- **Sign-in errors in English:** `auth.service.ts` answers with English messages ("Member not
  found. Please contact an administrator.", "Member account is disabled", "Member not found in
  this band...", "Account is disabled") and `Login.vue` shows them as they come. Send a `code`
  with each (`MEMBER_NOT_FOUND`, `MEMBER_NOT_IN_BAND`, `MEMBER_DISABLED`), translate it in the
  page with new `login.errors.*` keys in the three languages, and fall back to
  `login.loginFailed` for anything else.
- **Band isolation:** the notes are read and written through the existing expense queries,
  which already filter by the band of the request's subdomain; nothing new reads across bands.
- **The manual:** in `frontend/src/manual/`, `entrar.md` quotes the new Portuguese message
  instead of the English one, `idioma.md` drops the line about server errors in English, and
  `financeiro.md` mentions the Observação.

**Done when:** specs show the delete confirmation and error texts, inactive members marked
"Inativo", and each sign-in error code shown in Portuguese; a backend test shows notes saved,
updated and returned on an expense; `/verify` shows a note surviving a reload and the delete
confirmation naming the entry; the manual parts above are updated.
