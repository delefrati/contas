The band sometimes plays one version of a song, a live take or a cover, and not the one that
comes up first. Each song gets an optional Spotify link to the version the band plays, set in
the song's form in Músicas and opened from the list. The playlist ticket (MB-17) builds on
it.

- **What is stored:** a nullable `spotify_track_id` (`VarChar(22)`) on `songs`, with a Prisma
  migration. The API takes a link and keeps only the track ID, and answers with the ID and the
  `https://open.spotify.com/track/<id>` link made from it.
- **The forms a link comes in:** `https://open.spotify.com/track/<id>`, with a locale path
  (`/intl-pt/track/<id>`) or a `?si=` query, and `spotify:track:<id>`. Anything else, an album, a
  playlist, an artist or another site, is refused with a message in the form, in `pt.json`,
  `en.json` and `es.json`.
- **Clearing it:** an empty field removes the link.
- **The list:** a song with a link shows a Spotify icon that opens it in a new tab (on a phone,
  the Spotify app); on a phone it also sits in the three-dot menu as **Abrir no Spotify**.
- **The setlist:** the event page shows the same icon next to each song that has a link.
- **Import:** `Título - Artista` lines are unchanged and bring no link.
- **Offline:** the link is in the songs the app keeps on the phone, so it still shows offline.
- **Band isolation:** the column is read and written through the existing song queries, which
  already filter by the band of the request's subdomain.
- **The manual:** `musicas.md` explains the field and the icon, `evento.md` the icon in the
  setlist, and the Músicas screenshot is taken again.

**Done when:** a backend test shows each link form saved as the track ID, a bad link refused
and an empty one clearing it; specs show the icon and the menu item; `/verify` shows a pasted
link surviving a reload and opening the track; the manual parts above are updated.
