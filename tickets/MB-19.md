The logs page (`/registros`) shows only the band's latest 100 entries, with no way to find one
by what it did or who did it, or to go back further than those 100. Add filters above the list
and a way to load older entries.

- **Filters:** by action (`CREATE`, `UPDATE`, `DELETE`, `LOGIN`…), by resource, by member and
  by date range, combined. The API answers them in one `GET /api/logs` with query parameters,
  instead of the separate `/resource/:resource` and `/action/:action` endpoints the page
  doesn't use.
- **Older entries:** a "load more" at the end of the list fetches the next page, newest first,
  keeping the filters. It disappears when there's nothing older.
- **Band isolation:** every query keeps the `bandId` of the request's subdomain, as
  `LogService.findAll` does now; a filter by member only matches that band's members.
- **Phone:** the filters fold away as the finance page's do, and the list stays within the
  screen's width.
- **Translations:** the new labels in every language in `frontend/src/i18n/locales`.
- **The docs:** the manual's `registros.md` says how to filter and load more, and its
  screenshot is taken again.

**Done when:** backend tests show the filters combined, paging and band isolation; the logs
spec in `cypress/e2e/logs.cy.js` filters and loads older entries; checked in a browser on
desktop and phone.
