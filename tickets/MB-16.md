A playlist can only be created in someone's Spotify account, so the app needs one connected.
Add a **Spotify** section to Configurações that connects an account with Spotify's sign-in,
shows which account is connected, and disconnects it. Whether the account is each member's or
one for the band is what MB-14 decides; this ticket follows that answer.

- **Connecting:** the Authorization Code flow with PKCE, asking only for the playlist scopes.
  The callback is on the central host and hands back to the band's subdomain, as MB-14 settles;
  the `state` is signed, short-lived and names the band and the member, and a callback with a
  bad or old `state` is refused.
- **What is kept:** the Spotify user's ID and name, the refresh token encrypted at rest, and
  the access token only in memory until it expires, in a new table with a Prisma migration.
- **Refreshing:** an expired access token is refreshed before a call; a refresh Spotify refuses
  (the member removed the app in Spotify) marks the account disconnected and asks to connect
  again.
- **Disconnecting** deletes the tokens.
- **A disabled member:** their connection stops working with the rest of their access.
- **Cancelling** on Spotify's page comes back to Configurações with nothing changed.
- **Not configured:** without the Spotify keys in the server's `.env`, the section doesn't show.
- **Band isolation:** the connection belongs to a band (and a member, if MB-14 says so) and is
  read only for the band of the request's subdomain; the central callback writes to the band
  the signed `state` names, never one from the query.
- **The logs:** connecting and disconnecting are written to the Registros.
- **The docs:** `configuracoes.md` explains connecting and disconnecting, with a new screenshot;
  `DEPLOY-OCI.md` has the Spotify app's redirect URI and the encryption key.

**Done when:** backend tests show the callback with a good, a forged and an expired `state`, a
token refreshed and a refused refresh disconnecting; a spec shows the section connected and
not; `/verify` shows an account connected and disconnected against Spotify; the docs above are
updated.
