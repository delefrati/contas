Every band's playlists are made in one Spotify account that belongs to minhabanda.com, because
Spotify allows a Development Mode app only 5 users (MB-14). Add a **Spotify** page to the admin
panel where a super admin connects that account with Spotify's sign-in, sees which account is
connected and whether it still works, and disconnects it. Band members never connect anything.

- **Connecting:** the Authorization Code flow, asking only for `playlist-modify-public`, with
  the redirect URI from `SPOTIFY_REDIRECT_URI` (`https://minhabanda.com/api/admin/spotify/callback`,
  and `http://127.0.0.1:8001/...` locally, since Spotify refuses `localhost`).
- **The callback** arrives as a browser redirect without the admin's token, so it is not behind
  `AdminAuthGuard`: it accepts only a `state` that is signed, single-use, a few minutes old at
  most and names an active super admin, and refuses anything else. It then sends the browser
  back to the admin page.
- **What is kept:** one connection for the whole platform, in a new table with a Prisma
  migration: the Spotify user's ID and name, the refresh token encrypted with AES-256-GCM keyed by
  `SPOTIFY_TOKEN_KEY`, and who connected it and when. The access token stays in memory.
- **Refreshing:** an expired access token is refreshed before a call, and a new refresh token in
  the answer replaces the stored one. A refresh Spotify refuses (`invalid_grant`) marks the
  connection broken; the admin page says so and offers to connect again.
- **Disconnecting** deletes the tokens. Playlists already made stay in the account.
- **For MB-17:** a service other modules call to get a valid access token, or to learn there is
  no working connection.
- **Cancelling** on Spotify's page comes back to the admin page with nothing changed.
- **Not configured:** without the four `SPOTIFY_*` variables, the page says Spotify isn't set
  up and the band pages show no Spotify buttons.
- **Band isolation:** the connection belongs to the platform, not to a band; only super admins
  on the central host can read or change it, and no token ever reaches a band's page.
- **The logs:** connecting and disconnecting are logged as admin actions.
- **The docs:** `admin.md` in the manual explains the page, with a screenshot; `DEPLOY-OCI.md`
  section 8 already has the app's setup, and `.env.prod.example` gets the four variables.

**Done when:** backend tests show the callback with a good, a forged, a reused and an expired
`state`, the refresh token stored encrypted, a rotated refresh token kept and a refused refresh
marking the connection broken; a spec shows the page connected, broken and not set up;
`/verify` shows the account connected and disconnected against Spotify; the docs above are
updated.
